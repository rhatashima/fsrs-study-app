# 要件定義 (REQUIREMENTS)

最終更新: 2026-10-04 / Phase 0（改訂 1）

## 1. 目的

事前に作成した問題（カード）を、FSRS（ts-fsrs）で計算したタイミングで復習する個人用の汎用学習 Web アプリ。

- AI が学習のたびに問題を生成するシステムではない。教材は事前に作成し、CSV/JSON でインポートする。
- 最初の教材は「日本城郭検定3級」。ただし城郭専用にはせず、美術検定・歴史系検定など任意の教材を追加できる。
- 次の4つを明確に分離する：**教材データ / FSRS 復習スケジュール / 学習履歴 / UI**。
- 教材を修正・追加しても学習履歴を失わない。

## 2. 利用者・利用環境

- 利用者は本人 1 名のみ。一般公開しない。
- PC ブラウザとスマートフォン（PWA としてホーム画面に追加）の複数端末から、同じ学習データを使う。
- 不要：多数ユーザー運用、課金、組織管理、管理者ダッシュボード、SNS、ランキング、共有。

## 3. 技術制約

| 区分 | 採用 |
|---|---|
| Frontend | React + TypeScript + Vite |
| FSRS | ts-fsrs（独自実装禁止。Phase 0 時点の最新は v5.4.2） |
| 認証 | Firebase Authentication（Google ログイン） |
| DB / 同期 | Cloud Firestore |
| Hosting | Firebase Hosting |
| App | PWA |

- Firebase **Spark（無料）プランのみ**で運用する。Cloud Functions、Cloud Storage for Firebase（2024年10月以降、新規バケットは Blaze が必要）など、Blaze プランが必要な機能は使わない。
- ライブラリの API・バージョンは実装時点の公式ドキュメント／型定義で確認する。

## 4. 機能要件

### 4.1 認証・アクセス制御
- Google ログイン。
- 許可された 1 ユーザー（Owner UID）だけが Firestore のデータを読み書きできる。**UI ではなく Firestore Security Rules で強制する。**
- 許可されていないアカウントでログインした場合は、日本語で「このアカウントは利用できません」と表示する。

### 4.2 学習（FSRS モード）
- 短答式。問題表示 → 頭の中で回答 → 「答えを見る」→ 正答・解説・画像を表示 → Again / Hard / Good / Easy で自己評価 → 次の問題。
- 文字列による自動正誤判定はしない。
- 各評価ボタンに、押した場合の次回予定（例：「10分」「3日」）を表示する。
- 期限が来た復習カードを新規カードより優先する。
- 1日あたりの新規カード数を教材ごとに設定できる（初期値 10）。
- 学習中の Again 等で数分後に再出題されるカード（学習ステップ）は同じセッション内で再出題する。

### 4.3 ホーム
- 選択中の教材名、今日の復習カード数、今日の新規カード数（残り）、学習開始ボタン。

### 4.4 教材
- 複数教材の作成・編集・切り替え。教材を選ぶと、その教材の学習状況・統計を表示する。
- 教材名・カテゴリー名はコードにハードコードしない（すべてデータ由来）。
- カードは削除せず「アーカイブ（非表示）」にする。履歴は保持する。

### 4.5 インポート
- CSV / JSON を一括インポート。取り込み先の教材は UI で選択する。
- 取り込み項目：id, question, answer, explanation, category, subcategory, tags, examDifficulty（問題の難易度 1〜5、任意。`difficulty` 列も同じ意味として受け付ける）, importance（重要度 1〜5、任意）, imageUrl, source, notes。
- **id は必須**（重複判定のキー）。
- 取り込み前にプレビューを表示：新規 / 更新 / 変更なし / エラー の件数と内容。
- 既存 id の扱いを選択できる：**更新する** または **スキップする**。
- カードを更新しても ReviewState / ReviewLog は削除・変更しない。
- 不正な CSV、必須項目欠落、ファイル内の id 重複は行番号付きでエラー表示し、エラー行は取り込まない。

### 4.6 画像付きカード
- `imageUrl` がある場合のみ画像を表示。ない場合は通常表示。
- 画像読み込み失敗時は代替表示（「画像を読み込めませんでした」）を出し、学習は継続できる。
- 画像の置き場所：外部 URL（https）または Firebase Hosting の `public/images/` 配下の相対パス。

### 4.7 成績・分析
教材ごと・カテゴリーごとに以下を表示：

| 指標 | 定義 |
|---|---|
| カード総数 | アーカイブされていないカード数 |
| 学習済みカード数 | 1回以上レビューしたカード数 |
| 未学習カード数 | 総数 − 学習済み |
| 総レビュー回数 | レビュー回数の合計 |
| Again 率 | Again 回数 ÷ 総レビュー回数 |
| Good 以上の割合 | (Good + Easy) ÷ 総レビュー回数 |
| 直近の学習数 | 直近 7 日間の日別レビュー数 |

- これらは「自己評価の割合」であり、FSRS の内部値（安定度・難易度・想起確率）とは別物として表示する。「正答率」という語は使わない。
- 統計は集計ドキュメントから表示し、ReviewLog を毎回読み込まない。カテゴリー変更後などに数値を正確に合わせる「再集計」を手動で実行できる。

### 4.8 設定
- 1日の新規カード数（教材ごと）、1日の区切り時刻（初期値 4:00）、目標保持率（request_retention、初期値 0.9）。
- ログアウト。

### 4.9 PWA
- manifest、アイコン、インストール可能な設定。
- オフライン編集同期は初期版では実装しない（アプリ本体のキャッシュのみ）。

## 5. 非機能要件

- **mobile-first**。片手操作。評価ボタンは画面下部に大きく配置（高さ 56px 以上目安）。
- 日本語 UI。Deck / Note Type / Field / スケジューラー内部状態などの内部構造を利用者に見せない。
- 主要画面：ホーム / 学習 / 教材 / 成績 / 設定。
- エラーでアプリ全体が落ちない（Error Boundary + 各処理での日本語エラー表示）。
- Firestore の読み書き回数を不必要に増やさない（無料枠：読み取り 5万/日、書き込み 2万/日）。画面を開くたびに全カード・全 ReviewState を読み込む設計にしない。
- リロードしてもデータが壊れない（レビュー保存は ReviewState・ReviewLog・集計をアトミックに書く）。
- ReviewLog から ReviewState を復元・監査できる（レビュー前後の FSRS 状態と、使った FSRS 設定・ts-fsrs バージョンを記録する）。

## 6. エラーハンドリング対象

| 事象 | 対応 |
|---|---|
| Firestore 読み込み失敗 | 再試行ボタン付きのエラー表示 |
| 保存失敗 | 「未保存」表示と再試行。未保存がある状態で離脱しようとしたら警告 |
| ログイン失敗 / 未許可アカウント | 日本語メッセージ |
| 不正な CSV / JSON、必須項目欠落、重複 id | 行番号付きでプレビューに表示し、取り込みを止める／該当行を除外 |
| 画像読み込み失敗 | 代替表示 |
| FSRS 状態欠落・破損 | 最新の ReviewLog のスナップショットから復元し、警告を出す。ReviewLog もなければ未学習として扱う |

## 7. 将来拡張（設計上の受け皿のみ用意し、MVP では実装しない）

- 模擬試験モード：FSRS スケジュールとは独立にカードを抽出し、ReviewState を変更しない。結果は別コレクションに保存。
- FSRS パラメータ最適化（ReviewLog から）。
- 高度な分析（想起確率分布、予測レビュー数など）。
- オフライン学習・同期。
- FSRS 設定変更後に、全 ReviewLog から予定を再計算する機能。

## 8. MVP 完成条件

- PC ブラウザ / スマートフォンで使用できる。PWA としてホーム画面に追加できる。
- Google ログインでき、許可ユーザーだけがデータにアクセスできる（Rules で強制）。
- 教材を切り替えられる。CSV または JSON をインポートできる。
- 新規カードを学習でき、期限が来たカードが復習対象になる。
- Again / Hard / Good / Easy で FSRS が次回予定を計算し、結果が Firestore に保存される。
- 別端末から同じ学習履歴を利用できる。画像付きカードを表示できる。
- 基本的な学習統計を確認できる。
- 教材を更新しても学習履歴が保持される。リロードしてもデータが壊れない。
- typecheck / lint / test / build がすべて成功する。

## 9. 開発用データ

- 本物の城郭検定問題集は作らない。ダミー 20 問程度（城郭用語・縄張り・石垣・天守・城郭史の複数カテゴリー、画像付き 1〜2 問）。
- 教材「日本城郭検定3級」と「テスト用教材」の 2 つ。
